# Автовыкладка сайта из GitHub

Правите сайт через Claude Code, делаете push, и через минуту правка на сайте. Каждая версия сохраняется, к любой можно вернуться.

- Сайт: https://yoririkunagi.github.io/site-autodeploy/
- Журнал выкладок: https://yoririkunagi.github.io/site-autodeploy/_deploys/
- История запусков: вкладка **Actions** этого репозитория

## Что происходит после каждой правки

1. **Проверка кода.** Разметка HTML, синтаксис PHP, битые ссылки, случайно попавшие пароли и `.env`.
   Если что-то не так, выкладка не начинается и сайт остаётся прежним. В Actions будет красный крестик с понятной ошибкой.
2. **Резервная копия.** Новая версия целиком сохраняется в архив (ветка `backups`) под своим номером.
3. **Выкладка** на сервер.
4. **Проверка живого сайта.** Страницы открываются, на главной есть форма заявки и телефон.
   Список проверок лежит в `deploy/smoke-checks.txt`, его легко дополнить.
5. Если живой сайт проверку не прошёл, **прошлая версия возвращается автоматически**, а в журнале появляется пометка.

## Как вернуть прошлую версию

Actions → «Проверка и выкладка сайта» → Run workflow → номер версии из журнала.
Или попросите Claude Code: «верни сайт на версию 3».

Откат меняет только то, что сейчас на сайте. Код в репозитории остаётся новым, и следующая правка выложится уже с ним.
Если правку нужно отменить насовсем, попросите Claude: «отмени последнюю правку» — он сделает `git revert`, и это пройдёт как обычная выкладка.

## Ваш сервер

В этом репозитории сайт выкладывается на GitHub Pages. Для обычного хостинга или VPS тот же процесс работает по SSH
(`deploy/server/deploy-ssh.sh`): версии лежат в `releases/`, сайт смотрит на ссылку `current`, переключение мгновенное.
Перед выкладкой дополнительно делается дамп базы данных.
